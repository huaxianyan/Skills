# 进度记录模板与实例

主文件「开发进度文档」一节的展开。要建新项目、给已有项目补进度文档，或把已有的记录从助手私有目录搬进仓库时读它。

两个形态的骨架都放 `docs/` 下，跟代码一起提交。

## 单一时间线形态

适合长期项目。文件放 `docs/STATUS.md`，头部写清当前主线，正文按时间追加。

```markdown
# 实施状态

## 当前主线

<两三句话说明现在在做什么、为什么>

## STATUS-007：<本轮主题>

- 日期：2026-03-14
- 仓库：api `4f2c1ab → 91b0e77`
- 验证：`go test ./...` 全通过；真机走查 12 项全过
- 结论：<一句话>
- 边界：<没覆盖的部分>
- 下一步：<动作>
```

编号顺序递增，不要复用。倒序还是顺序都行，选定后不要来回换。

体量预算：全文件不超过 500 行或 30 条，单条不超过 30 行。超限就把已完结条目整批归档，写法见下面「归档」。

## 决策文件加日期流水

适合一天内多轮交付、需要区分「定下来的」与「当轮过程」的项目。两个文件都放仓库里。

```text
docs/handoff/
  DECISIONS.md       # 长期决策，只在被推翻时才改
  2026-03-14.md      # 当日流水，追加
```

`DECISIONS.md` 只放稳定结论：仓库定位、边界、定下来的决策、容易踩的坑。日期文件放当轮过程：试了什么、哪条路不通、最后落在哪。两个文件也各受同样的体量预算约束，DECISIONS 里被推翻的决策就地删除，历史归给进度流水。

不要为了省事把它放到助手或工具的私有目录（`.pi/`、`.claude/`、`.workbuddy/`）。换个工具就没人看得到，也谈不上交接。私有目录只放临时草稿。

## 归档

条目池超过预算时把已完结的旧条目整批移到 `docs/archive/`，文件名带覆盖范围：

```text
docs/archive/STATUS-2026-10-03_1014.md   # 该时段的条目，一次成型后只读
```

归档文件头部写覆盖范围与条目序号段，正文原样保留。正文头部留三样：刷新过的「当前主线」、仍在生效期的最近几条、归档索引（一行一个归档文件，写明覆盖的日期与序号段）。

归档前先提交一次现状。切分是纯移动，出问题可以整体回滚。往归档里追加条目即违规：归档是快照，不是第二个收件箱。

需要旧事实时按索引定位归档文件，`grep` 单条，不整读。读取成本与历史厚度无关，这正是归档的目的。

## 写好一条的四个要求

### 写清验证强度

同一句结论，实测和推断的价值差一个量级。分开写：

- 实测：`六次独立复现，恢复时间 2.28 到 2.62 秒，分辨率 0.1 秒`
- 推断：`前台服务失效时的兜底作用未实测，属推断`

### 写清边界

至少回答一遍：样本多少、覆盖哪些平台、哪种条件没构造、结论在什么前提下成立。没有边界声明的结论，下一个执行者会当成普遍成立。

### 推翻旧结论时指名作废

```markdown
- 2026-03-18 实测否证条目 12 的推断：「豁免的价值是前台服务失效时的兜底」。
  反证：停掉服务后连接立即断开，且没有任何路径把它拉回来。
```

不写这一句，旧结论会一直躺在文档里被后人引用。

### 数字落地

`性能大幅提升` 没有交接价值。换成 `p99 从 120 ms 降到 40 ms，样本 2000 次`。

## 一条完整实例

```markdown
## STATUS-014：通知清除失败的判据修正

- 日期：2026-03-14
- 仓库：android `f1c60e6 → 1acef54`、extension `6ce265f → f4a6182`
- 现象：用户报「点了多次清除无效，手动划掉后浏览器侧才同步消失」
- 根因：判据用了 `isClearable`，它对单条取消的语义过宽；真正该判的是 `isOngoing`
- 改动：判据换成 `isOngoing`；失败原因不再被静默吞掉
- 验证：真机三个用例全过，其中 `FLAG_NO_CLEAR` 那条改前是 `INTERNAL_ERROR`，改后 `SUCCEEDED`
- 边界：只覆盖 AOSP 一台设备；厂商 ROM 的锁屏限制未测
- 下一步：等用户在日常使用中确认，无需再写测试
```

## 交接前自查

- 进度文档在仓库目录里，且跟当轮代码一起提交了。
- 头部「当前主线」反映的是本轮收尾后的现状，不是几天前的。
- 文件体量在预算内；超了就先归档再提交本轮。
- 最新一条记录的日期是不是今天。
- SHA、分支、CI 结果是否现场核对过。
- 未完成项有没有写清阻塞条件。
- 没有内网地址、服务器路径、设备序列号或凭据。需要指向这些信息时，写的是「见本地 `AGENTS.md`」。
- 被推翻的结论是否已指名作废。
