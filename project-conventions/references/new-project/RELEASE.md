# 构建与发布

## 发布前置

- 版本号写在哪个文件，怎么改（功能走次版本、修复走修订版本）。
- 发布说明必须存在：`docs/release-notes/v<版本>.md`，缺失时流水线直接失败。
- 发布前必须跑通：`<测试命令>`、`<构建命令>`。

## 产物

- 命名：`<项目名>-<版本>-<架构>.<后缀>`。
- 落点：`dist/`（被忽略，不入库）。
- 校验：同时产出 `.sha256`。

## 流程

1. 改版本号、写发布说明、提交。
2. 推 `main`。
3. 打标签 `git tag -a v<版本> -m "<项目名> <版本>"` 并推标签。
4. 流水线构建、测试、打包、建 Release；发布说明用 `gh release edit --notes-file` 换成正式版。
5. 已发布的标签不改写，修复走递增版本。

## 回滚

- 代码：`git revert`。
- 产物：留上一个版本的安装包与校验和，说明存放位置。
